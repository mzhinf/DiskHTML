# 暂停、取消与恢复语义

## 文件边界

恢复点是“已在 SQLite 事务中完整提交的文件”。进程中断时，正在计算的单个文件从头读取，
不序列化 `hashlib` 的内部状态。

## 状态转换

- `PENDING` 可进入 `SCANNING`、`CANCELLED` 或 `FAILED`。
- `SCANNING` 可进入 `PAUSED`、`COMPLETED`、`CANCELLED` 或 `FAILED`。
- `PAUSED` 可继续到 `SCANNING`，也可取消或失败。
- `CANCELLED` 和 `FAILED` 保留已提交结果，可显式恢复到 `SCANNING`。
- `COMPLETED` 是终态，不能恢复或重新打开写入。

暂停只阻止提交新的文件任务，并等待文件边界；取消应尽快停止派发，已完成的事务不回滚。

## 恢复复用条件

已有记录只有同时满足以下条件才可复用：

1. `hash_status` 为 `OK`；
2. 文件大小与记录一致；
3. 纳秒修改时间与记录一致。
4. 记录算法与当前配置对该文件大小推导出的实际算法一致。

不满足条件的文件必须从头重新计算。权限错误、文件消失和扫描中变化都要写入错误记录，
不能静默跳过。
## 扫描边界与进度

- Windows 本地绝对路径在文件系统访问时自动转换为扩展路径前缀，以支持超过传统 260 字符限制的路径。
- 默认不跟随符号链接、目录联接或其他重解析点；跳过行为会写入错误记录。
- 文件在 Hash 前后会比较大小与纳秒修改时间。变化后会重试；仍变化则写入 `UNSTABLE`，不保存可信 Hash。
- 进度事件包含已发现文件数、已完成文件数、已 Hash 字节数、当前路径和吞吐率。ETA 以已枚举字节估算；未发现的后续文件不参与该估算。

## 暂停与取消

暂停请求会在下一个文件边界把任务状态写为 `PAUSED`，继续后回到 `SCANNING`。取消时，已在 SQLite
事务中提交的文件保持有效，正在处理或尚未开始的文件会在恢复时重新计算。后台扫描线程可以复用同一
数据库连接，但所有数据库事务由锁串行化，确保批量写入的原子性。
