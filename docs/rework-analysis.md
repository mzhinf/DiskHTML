# 返工原因与防复发分析

## 结论

多轮返工不是单一的 UI 审美、PowerShell 版本或编码问题，而是产品边界后置、渲染层高耦合、测试层偏离用户行为、Windows 工具链边界不清和发布门禁缺失共同造成。

## 根因表

| 层级 | 根因 | 证据 | 造成的结果 |
|---|---|---|---|
| 产品 | 先实现项目式 SQLite GUI，之后才冻结为“EXE 只生成、HTML 只浏览” | 早期提交实现项目、任务、恢复和报告窗口；`4b8707e`、`48286dd` 才精简为当前工作流 | 大量原功能被删除，界面和文档反复重写 |
| 术语 | “冷备/backup”先进入代码，后确认只是使用场景，不是产品功能名 | `a81f9c3`、`359985a` 使用旧术语；之后切换为 `snapshot` | 命令、UI、说明多次改名并出现残留 |
| 比较模型 | 先做两份结果比较，后确认目标是“HTML 树中任意目录对本机任意目录” | `359985a` 后才形成 `compare-source` 和快照目录选择 | 早期比较入口与最终需求不一致 |
| UI 规格 | Snap2HTML/VSCode 树、滚动、详情高度和状态颜色没有在首轮形成可执行规格 | `737eec3` 到 `500d74d` 连续多次修改同一目录树和详情区 | 用户持续承担视觉验收，局部修复互相覆盖 |
| 渲染实现 | CSS、JavaScript 和 HTML 被集中在 `archive_ui.py` 的超长内嵌字符串 | 单文件同时承担树、搜索、排序、详情、链接、CSV、状态传播 | 小改动难审查，容易破坏相邻布局和交互 |
| 测试 | 大量测试只断言 HTML 源码包含某字符串，没有执行真实浏览器 DOM 行为 | `tests/test_html_archive.py` 主要检查 CSS/JS/SVG 片段 | 测试绿灯时仍可能出现空报告、错误搜索、链接遮挡 |
| EXE 入口 | 初版 PyInstaller 入口无论是否带参数都进入 GUI | 后续才在 `gui_entry.py` 按参数分流 | 用户命令只启动窗口，无法生成 HTML |
| 编码 | 非 UTF-8 文本管道把不可表示字符写回为真实 `?` | `48286dd` 和 `4eb247c` 引入连续问号，`46ad7a5` 后才增加编码守卫 | 中文源码和 EXE 路径文案损坏 |
| 打包 | onedir 与“单 EXE”口径未区分，测试没有运行独立发布包 | 初版脚本未显式模式；只复制启动器缺 `_internal/python312.dll` | 用户拿到的 EXE 无法单独启动 |
| 流程 | “代码已提交/字符串测试通过”被当作完成，没有发布包和真实页面门禁 | 目录树一小时内多次补丁提交；无 GitHub CI | 同类问题在后续轮次反复出现 |

## PowerShell 问题的准确拆分

| 场景 | 是否必要 | 当前作用 | 整理后的处理 |
|---|---:|---|---|
| Windows 构建 | 否 | 旧 `.ps1` 做路径、清理、PyInstaller 调用和 ZIP | 核心迁入 `scripts/build_windows.py`；`.ps1` 只做可选转发 |
| 扫描与 SHA-256 | 否 | 不参与文件枚举或 Hash | 继续由 Python 完成 |
| 卷容量、卷标、文件系统、卷 GUID | 否 | Python 标准库和 Win32 API | 保持原实现 |
| 物理磁盘型号、序列号、分区 | 当前为可降级依赖 | 调用 `Get-Partition`/`Get-Disk` | 查询失败写入 `capture_error`，不阻止报告；未来可用 Win32 `DeviceIoControl` 替换 |

PowerShell 7 能降低旧 Windows PowerShell 输出编码差异，但“装了 7.x”不等于所有终端和自动化宿主都会使用它。源码变成真实问号的直接原因是错误编码内容被写回文件，不只是控制台显示乱码。

## 本轮已经建立的防线

- Python 构建入口成为唯一构建逻辑来源，PowerShell 降为薄包装。
- 发布验证会解压真实 ZIP、运行 EXE、生成包含中文文件名的 HTML 和 SQLite。
- GitHub Windows CI 执行格式、静态检查、完整测试、构建和独立发布包验证。
- 所有自有 Python/PowerShell 文件必须有用途说明，UTF-8 和损坏字符由测试检查。
- README、文档索引、架构表、用户指南和发布清单统一到当前三个任务。
- 发布清单明确 onedir ZIP、`_internal`、许可证、第三方声明和 Win10/11 验收。

## Tkinter/ttk 迁移结果

- 桌面界面已从 PySide6 切换为 Python 标准库 `tkinter/ttk`；扫描、Hash、SQLite、HTML 数据格式和三任务流程保持不变。
- PyInstaller 发布包携带 Python 与 Tcl/Tk 运行时，不再包含 PySide6、Shiboken6 或 Qt 文件；构建和许可证审计会把 Qt 残留视为错误。
- 标准 Tk 不提供可靠的 Windows 资源管理器拖放接口，因此本版本保留直接输入和选择按钮，不引入额外拖放二进制依赖。
- 发布许可证由最终目录包反向生成和校验，未知组件、版本、许可证来源或声明不一致都会阻断 ZIP 创建。
