# 架构决策记录

## ADR-001：SQLite 作为权威数据源

- **状态：** 已接受
- **决策：** 每个项目使用一个版本化 SQLite 数据库。CSV、JSON 和 HTML 都是可重新生成的导出物。
- **原因：** SQLite 提供事务、索引和流式查询，适合数百万文件记录以及中断恢复。

## ADR-002：单写入者和有界并发

- **状态：** 已接受
- **决策：** 文件枚举和 Hash 读取可并发，SQLite 只由扫描编排线程写入；所有工作队列必须有界。
- **原因：** 避免 SQLite 写入竞争，并确保文件数量增长时内存保持有界。

## ADR-003：SHA256 永远必算

- **状态：** 已接受
- **决策：** SHA256 是内容一致性的最终依据。SHA512 只能作为可选附加摘要。
- **原因：** 维持长期可比较的统一基线，不让配置选择削弱校验语义。

## ADR-004：路径比较键版本化

- **状态：** 已接受
- **决策：** 同时保存保真的相对路径和 `path_key`。版本 1 把分隔符统一为 `/` 并执行
  Unicode `casefold`；发生键冲突时记录错误，不静默覆盖。
- **原因：** Windows 默认不区分大小写，但报告仍需保留用户看到的原始路径。

## 模块边界

- `config`：版本化配置和参数校验。
- `models`：领域数据、状态机和稳定错误码。
- `scanner`：枚举、Hash、暂停控制及单写入编排。
- `database`：模式迁移、事务和流式查询。
- `disk`：Windows 卷及物理介质信息适配。
- `cli`：参数解析、退出码和应用服务调用。
- 后续的 `report`、`compare` 与 `ui` 只能通过公共模型和服务访问核心逻辑。
