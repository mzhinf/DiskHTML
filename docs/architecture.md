# 架构决策记录

## ADR-001：HTML 是默认用户交付物，SQLite 是内部索引

- **状态：** 已接受，替代“每个用户项目以 SQLite 为权威交付物”的早期决策。
- **决策：** 默认冷备由单个 HTML 快照交付，默认比较由单个 HTML 报告交付。扫描阶段使用临时 SQLite 实现事务、排序和有界写入；生成成功后清理临时索引。
- **原因：** 用户需要类似 Snap2HTML 的直接可打开、可传递和可归档结果，而非维护数据库文件。
- **影响：** HTML 必须内嵌快照数据和可视化脚本，且可被后续比较读取。原有 SQLite 项目功能保留为高级的中断恢复、维护和旧式目录报告流程。

## ADR-002：单写入者和有界并发

- **状态：** 已接受。
- **决策：** 文件枚举和 Hash 读取可并发，SQLite 只由扫描编排线程写入；所有工作队列必须有界。
- **原因：** 避免 SQLite 写入竞争，并确保扫描阶段的内存保持有界。

## ADR-003：SHA256 永远必算

- **状态：** 已接受。
- **决策：** SHA256 是内容一致性的最终依据；SHA512 只能作为可选附加摘要。
- **原因：** 保持长期可比较的统一基线。

## ADR-004：路径比较键版本化

- **状态：** 已接受。
- **决策：** 同时保存原始相对路径和 path_key。当前路径键统一分隔符并执行 Unicode casefold；键冲突记录错误，不静默覆盖。
- **原因：** Windows 默认不区分大小写，而报告仍需保留用户可见的原始路径。

## 模块边界

- config：版本化配置和参数校验；
- models：领域数据、状态机和稳定错误码；
- scanner：枚举、Hash、暂停控制和单写入编排；
- database：临时或高级项目索引的迁移、事务和流式查询；
- html_archive：单文件 HTML 冷备、读取和 HTML 快照比较；
- report：高级 SQLite 项目的旧式目录报告；
- compare：基于路径键和 SHA256 的比较归并；
- cli：默认 HTML 工作流及高级项目命令；
- ui：图形界面，只调用公共服务。

详细的 HTML 交付格式和可视化约束见 [HTML 冷备与比较设计](html-archive-design.md)。
