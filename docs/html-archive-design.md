# HTML 冷备与目录比较设计

## 目标

用户交付物始终是可直接离线打开的单个 HTML 文件：

- 冷备：扫描目录或文件，生成一个 .html 快照；
- 比较：从 HTML 冷备文件树选择一个历史目录，与本机任意目录比较，生成一个 .html 比较报告；
- 用户不必创建、打开、迁移或保管 SQLite 文件。

工作方式接近 Snap2HTML：HTML 是可传递和可归档的历史快照；DiskHTML.exe 负责选择历史目录和本机目录。

## 分层设计

~~~text
历史目录
    ↓ 扫描和 SHA256 计算
临时 SQLite 索引（仅生成期间）
    ↓ 原子发布
单文件可视化 HTML 冷备
    ↓ EXE 读取并选择历史目录
重定根后的历史文件清单 + 本机目录扫描结果
    ↓ 路径归并和 SHA256 判定
单文件可视化 HTML 比较报告
~~~

浏览器安全模型不允许本地 HTML 页面直接列举任意本机目录。因此“从 HTML 树选择目录”和“选择本机目录”在 DiskHTML.exe 中完成；浏览器只负责打开最终的离线可视化报告。

SQLite 用于生成期间的有界队列写入、扫描状态和顺序读取；生成成功后临时目录会自动清理。它不是默认交付物。

## 目录选择与比较语义

HTML 冷备包含文件清单及目录清单。EXE 将目录清单显示为树，根目录和每一个历史子目录都可选择。

选择历史目录后：

1. 仅保留该目录及其子目录中的文件；
2. 移除该历史目录前缀，使其成为比较左侧的根；
3. 扫描用户选择的本机目录，使其成为比较右侧的根；
4. 使用大小写无关路径键对齐，再以 SHA256 判定 MATCH、CHANGED、ADDED、MISSING 或 ERROR。

因此，历史目录“资料/照片”可直接与本机的任意目录比较，不要求两侧绝对路径相同。

## 可视化要求

- 冷备 HTML 使用类似资源管理器的左右布局：左侧为可展开层级文件树，单击目录即可筛选右侧文件；
- 每个文件记录并显示 SHA-256、Hash 状态、大小和错误信息；
- 支持按路径、状态和错误信息筛选；
- 列表初始渲染最多 500 行，可继续加载；
- 单击行可查看完整元数据；
- 比较报告显示左右来源和所选历史目录，并提供 MATCH、CHANGED、ADDED、MISSING、ERROR 状态筛选。

## EXE 功能范围

DiskHTML.exe 的默认界面只保留：

- 生成冷备 HTML；
- 比较冷备目录；
- 打开报告；
- 扫描配置；
- 暂停、继续、取消正在扫描的冷备或本机比较。

SQLite 项目管理、旧式任务表、恢复、错误列表和两份 HTML 的默认比较入口已从 EXE 界面移除。
