# 架构决策记录

## ADR-001：HTML 是默认用户交付物，SQLite 是内部索引

- **状态：** 已接受。
- **决策：** 默认冷备由单个 HTML 快照交付；默认比较由“HTML 快照中选定目录”与“本机目录”生成的单个 HTML 报告交付。扫描阶段使用临时 SQLite 实现事务、排序和有界写入；成功后清理临时索引。
- **原因：** 用户需要类似 Snap2HTML 的直接可打开、可传递和可归档结果，而非维护数据库文件。
- **影响：** HTML 必须内嵌快照数据和目录信息。EXE 负责选择历史目录及本机目录，浏览器只打开最终报告。

## ADR-002：目录比较由 EXE 协调

- **状态：** 已接受。
- **决策：** 选择历史目录、选择本机目录和本机扫描在 DiskHTML.exe 中完成；历史目录会重定根后与本机目录按相对路径比较。
- **原因：** 浏览器安全模型不允许本地 HTML 直接枚举任意本机目录。
- **影响：** EXE 默认不提供两份 HTML 比较入口，比较结果仍为离线 HTML。

## ADR-003：单写入者和有界并发

- **状态：** 已接受。
- **决策：** 文件枚举和 Hash 读取可并发，SQLite 只由扫描编排线程写入；所有工作队列必须有界。
- **原因：** 避免 SQLite 写入竞争，并确保扫描阶段的内存保持有界。

## ADR-004：SHA256 永远必算

- **状态：** 已接受。
- **决策：** SHA256 是内容一致性的最终依据；SHA512 只能作为可选附加摘要。

## ADR-005：路径比较键版本化

- **状态：** 已接受。
- **决策：** 同时保存原始相对路径和 path_key。当前路径键统一分隔符并执行 Unicode casefold；键冲突记录错误，不静默覆盖。

## 模块边界

- config：版本化配置和参数校验；
- scanner：枚举、Hash、暂停控制和单写入编排；
- database：临时或高级项目索引的迁移、事务和流式查询；
- html_archive：单文件 HTML 冷备、HTML 目录列表与“历史目录对本机目录”比较；
- exe_cli：DiskHTML.exe 的精简命令行入口；
- ui：HTML 冷备图形界面和目录树选择；
- report、cli：仅保留给高级 SQLite 项目兼容流程。

详细格式和交互见 [HTML 冷备与目录比较设计](html-archive-design.md)。
