# HTML 冷备与比较设计

## 目标

用户交付物是可直接用浏览器离线打开的单个 HTML 文件：

- 冷备：扫描目录或文件，生成一个 .html 快照；
- 比较：读取两个冷备 HTML，生成一个 .html 比较报告；
- 用户不必创建、打开、迁移或保管 SQLite 文件。

这使冷备的使用方式接近 Snap2HTML：复制一个 HTML 文件即可交付、归档和再次比较。

## 分层设计

~~~text
源目录或文件
    ↓ 扫描和 SHA256 计算
临时 SQLite 索引（仅生成期间）
    ↓ 生成、原子发布
单文件可视化 HTML 冷备
    ↓ 读取嵌入快照并归并
单文件可视化 HTML 比较报告
~~~

SQLite 仍用于生成期间的有界队列写入、扫描状态和顺序读取；生成成功后临时目录会自动清理。它不是默认交付物，也不需要浏览器直接加载 SQLite。

保留原有 SQLite 项目命令作为高级工作流：适用于长时间扫描中断后的恢复、维护已有项目以及原有目录式报告。默认用户路径应使用 backup 和 compare-html。

## HTML 数据格式

冷备 HTML 含有固定标识为 diskhtml-archive-data 的 JSON script 标签，数据包括：

- 格式版本、生成时间、扫描任务和卷信息；
- 文件统计；
- 以 Windows 大小写无关路径键排序的文件清单；
- 文件大小、时间、SHA256、Hash 状态及错误信息。

比较 HTML 使用同一机制，包含左右快照标识、状态统计和逐路径结果。路径文本中的 HTML 敏感字符会转义，避免破坏嵌入数据。

## 可视化要求

两个 HTML 都无需网络或浏览器扩展：

- 冷备报告显示文件、目录、已 Hash 与问题数量；
- 支持按路径、状态和错误信息筛选；
- 列表初始渲染最多 500 行，可继续加载，避免一次性创建大量 DOM；
- 单击行可查看完整元数据；
- 比较报告提供 MATCH、CHANGED、ADDED、MISSING、ERROR 状态按钮和统计。

## 约束与后续演进

单文件模式会让浏览器加载完整文件清单，因此超大目录会占用相应浏览器内存。生成端仍使用 SQLite 流程保障扫描阶段的稳定性；如需面向数百万文件的首屏渐进加载，可在不改变用户主入口的前提下增加 HTML 与旁路分片数据包模式。
